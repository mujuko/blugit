# blugit

近くのPC同士で、Bluetoothを使ってGitリポジトリを共有するCLIです。
LANやインターネットがない場所でも、`git clone` / `git pull` / `git push` で変更を受け渡せます。

リポジトリを公開するPCが**ホスト**、接続するPCが**ゲスト**です。
ゲストからリポジトリを操作するには、`blugit join` による端末登録が必要です。
登録には、申請時にホストの画面に表示される6桁の確認コードを、ゲスト側で入力する必要があります。
登録が成功すると、双方のプログラムが相手の公開鍵を保存します。登録後のGit操作では、コードの再入力は不要です。
アカウントやパスワードの作成は不要で、登録後のGit通信はBluetooth上のSSHで公開鍵認証・暗号化されます。
SSHはアプリに組み込まれているため、OSのSSHサーバー設定やポート開放は不要です。
同時に公開できるリポジトリは1つです。

現在は実機検証中です。Windows・macOS・Linuxのビルドと自動テスト、Windows／Macの両方向のBluetoothでのclone・push・pullを確認しています。
Linuxと残る実機項目の確認範囲は、[検証記録と実機確認手順](docs/validation.md)を参照してください。
独立したセキュリティ監査も未実施です。認証方式と採用ライブラリの制約は[設計](docs/architecture.md)に記載しています。

## インストール

両方のPCにGit、Rust stable、Bluetooth Classic（RFCOMM）対応アダプターが必要です。
BLE専用アダプターは使えません。OSごとのビルド環境も用意してください。

| OS | 必要な環境 |
|---|---|
| Windows | RustのMSVCツールチェーン、Visual Studio C++ Build Tools |
| macOS | Xcode Command Line Tools |
| Linux | BlueZ、D-Bus、`pkg-config`、`libdbus-1-dev`（Debian / Ubuntuの場合） |

インターネットに接続できるうちに、両PCでこのソースのディレクトリから実行してください。

```sh
cargo install --path . --locked --force
blugit --version
git-remote-blugit --version
```

`blugit` は共有・端末登録用、`git-remote-blugit` はGitが自動で呼び出す接続用プログラムです。
両方が `1.0.0` と表示されればインストール完了。コマンドが見つからない場合は、
Cargoのインストール先（通常はホームディレクトリの `.cargo/bin`）をPATHに追加してください。
インストール後のGit転送にインターネット接続は不要です。

## リポジトリを共有する

両PCのBluetoothを有効にしてから始めてください。OSから利用許可や接続確認を求められた場合は、内容を確認して許可してください。

### 1. ホストで共有を開始

共有先には、作業ファイルを持たず、履歴の受け渡し専用となる**bareリポジトリ**を使います。
まず空の共有先を作る例です。既存のbareリポジトリがあれば、`host` にそのパスを指定できます。

```sh
git init --bare --initial-branch=main demo.git
blugit host ./demo.git
```

既存の作業リポジトリから共有先を作る場合は、`git init` の代わりに
`git clone --bare ./project ./demo.git` を使ってください。元の作業リポジトリとは別のコピーになるため、以後の変更の受け渡しにはpush／pullが必要です。

画面に `Connection code: 00MX-8433-A77D` のような接続コードが表示されます。
この英数字12文字をゲストへ伝え、ホストは起動したままにしてください。
接続コードにはホストの接続先が含まれ、ゲストは近隣の端末を探索せずに接続できます。

### 2. ゲストの端末を登録

ホストから聞いた接続コードに続けて、ゲスト側で使う登録名を指定してください。
以下の接続コードは例です。実際にホストに表示されたものへ置き換えてください。

```sh
blugit join 00MX-8433-A77D demo
```

接続コードを入力すると登録申請が届き、ゲストに `Six-digit code:`、ホストに `JOIN ... CODE=123456` のような表示が出ます。
ここで使う6桁番号は、その申請を許可するための確認番号です。
ホスト操作者は相手の端末名・IDを確認し、その相手にだけ番号を伝えてください。
伝える相手を確認する方法として、対面での確認を推奨します。
ゲスト操作者は、ホスト操作者から受け取った番号を `Six-digit code:` に入力してください。
`Registered with ...` と表示されたら登録完了です。

`demo` はこのゲストPCに保存する接続先の名前です。名前には1〜32文字の英数字・`-`・`_`を使え、先頭は英数字、大文字と小文字は同じ扱いです。
別のPCから接続するときも、そのPCで登録が必要です。同じ `blugit://demo` を使いたい場合は、同じ名前で登録してください。

番号は1回限りで、有効期限は180秒。誤入力や期限切れの際は、同じコマンドで再申請できます。
ただし申請は同時に1件まで、番号の発行間隔は最低10秒です。登録操作はCtrl+Cで取り消せます。

端末名にはPC名が使われます。相手に分かりやすい名前にするなら、登録前に
`blugit device --name MacBook` のように指定することをおすすめします。名前を変更しても端末IDは変わりません。

### 3. 登録後のGit操作

登録時に決めた名前でcloneできます。共有ID・接続先・ホスト鍵は保存済みの登録から読み出すため、以後のGit操作にコードや番号の入力は不要です。

```sh
git clone blugit://demo work
cd work
```

空のリポジトリをcloneした際の警告は正常です。commitした変更は `git push -u origin main` で共有先へ送れます。
他の人の変更を取り込む場合は、`git pull --ff-only` を実行してください。
ホスト自身も編集するなら、別の作業コピーを `git clone ./demo.git host-work` で作れます。
同じ接続先へのGit操作は、1つずつ順番に実行してください。

## 共有を止める・再開する

ホストでCtrl+Cを押すと、新しい接続と登録待ちを止め、開始済みのGit転送が終わるまで待ちます。
すぐに中断する必要がある場合は、もう一度Ctrl+Cを押してください。Gitリポジトリ自体は削除されません。

再開には同じ `blugit host ./demo.git` を実行するだけです。
チャネルは空き状況に応じて自動選択されるため、再起動後に接続コードが変わることがあります。
変わった場合も、登録済みゲストは同じホストの接続口を自動で探し直します。再登録やoriginの変更は不要です。

ホストが停止中のGit操作は接続エラーになります。

## 端末のアクセスを取り消す

ホスト側の別ターミナルから、登録済み端末を確認できます。

```sh
blugit peers ./demo.git
blugit revoke ./demo.git DEVICE-ID
```

`DEVICE-ID` は一覧の64桁ID、または一意に特定できる8桁以上の先頭部分に置き換えてください。
端末名が同じでもIDで区別できます。

解除後の新しい接続は拒否されます。開始済みの転送は継続し、相手が取得済みの履歴や作業コピーも残ります。
再登録には、ホストが新しく発行する番号の確認が必要です。

端末の鍵や登録情報の保存先は `blugit device` で確認できます。
秘密鍵を含むため、このディレクトリの他人への配布やGitへの追加は避けてください。

## 接続できないとき

まずホストが起動中か、両PCのBluetoothが有効かを確認してください。
接続コードの入力間違いは、接続を始める前に検出できます。小文字やハイフンなしでも入力可能です。

登録名はリポジトリ固有の共有IDと結び付いています。ホストが別のリポジトリを公開した場合は、別の名前で登録してください。
接続コードは同じPC・チャネルなら同じ値になりますが、既存の登録名は元のリポジトリを指し続けます。

チャネルはBluetooth上の接続口の番号です。省略時はOSが空いている番号を自動選択します。
毎回同じ番号を使いたい場合は、ホストで明示できます。

```sh
blugit host ./demo.git --channel 8
```

明示した番号が使用中なら、ホストはエラーで終了します。別の番号で再実行するか、`--channel` を省略してください。

チャネルが変わると初回登録用の接続コードも変わります。登録済みゲストは、ホスト鍵と共有IDを照合して接続口を自動で更新するため、既存のoriginをそのまま使えます。

## 開発に参加する方へ

SSH切替前の未リリース版との互換性はありません。両端末を更新し、改めて `join` してください。
既定の状態保存先は `blugit/v2` です。`BLUGIT_HOME` や `--state-dir` を指定する場合は、新しいディレクトリを使ってください。

モジュール構成とテストの対応は[設計](docs/architecture.md)、確認範囲と実機手順は[検証記録](docs/validation.md)を参照してください。
自動テストは `cargo test --locked --features test-transport` で実行できます。
`test-transport` はIP接続で無線を代替するテスト専用機能のため、通常利用のビルドでは有効にしないでください。
