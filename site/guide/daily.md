# 毎日の使い方

登録が済んだ後の、ふだんの使い方をまとめます。

## 作業の流れ

<Role who="host" />が `blugit host` を起動している間、<Role who="guest" />はいつでも push / pull できます。

- 作業を始める前に、AIに「最新を pull して」と頼む
- ひとまとまりの作業が終わったら、「コミットして push して」と頼む
- push を断られたら、「pull してから push し直して」と頼む

こまめに pull と push をしておくと、コンフリクト（2人が同じ場所を変えてぶつかること）が起きにくくなります。
頼み方の一覧は、[Git講座のまとめ](../git/#summary)にあります。

::: tip 操作は1つずつ
同じ接続先へのGit操作は、同時に実行せず1つずつ行ってください。
:::

## 共有を止める

ホストのターミナルで Ctrl+C を押します。

<TerminalScreen
  who="host"
  :lines="[
    ['Sharing stopped; waiting for 1 connection(s). Press Ctrl+C again to abort.', '新しい接続の受付をやめ、実行中の転送が終わるのを待っています'],
  ]"
/>

- **1回押す**：新しい接続を受け付けなくなり、実行中の転送が終わるのを待ってから止まります。
- **もう一度押す**：転送の途中でも、すぐに止まります。

ゲストが push している途中で止めると、その push は失敗します。なるべく1回だけ押して、終わるのを待ちましょう。

## 共有を再開する

止めたときと同じコマンドを実行します。

```sh
blugit host ./demo.git
```

再開すると、**接続コードが変わることがあります**。それでも、登録済みのゲストは登録し直す必要はありません。

接続コードのうち、変わるのは11文字目の「接続口の番号」だけです。ホストの住所（最初の10文字）は同じなので、ゲストは保存してある住所と鍵を使って、新しい接続口を自動で探し直します。

<ConnectionCodeAnatomy />

::: info 再開直後は時間がかかることがある
接続口の番号が変わった直後の最初の接続は、探し直すぶん時間がかかることがあります。2回目からは、いつもの速さに戻ります。
:::

## ゲストを増やす・別のPCから使う

新しいゲストや、同じ人の別のPCは、それぞれのPCで `blugit join` して登録します。
[はじめての共有](./first-share)の「4. ゲスト：登録を申請する」と同じ手順で、ホストが今表示している接続コードを使います。

登録名は、PCごとに自由に決められます。同じ名前（例：`demo`）にしておけば、どのPCでも `blugit://demo` で使えます。

## 別のリポジトリを共有する

ホストが一度に共有できるリポジトリは、1つだけです。別のリポジトリを共有するときは、今の共有を止めてから `blugit host` を実行します。

ゲストの登録名は、登録したときのリポジトリと結び付いています。新しいリポジトリには、**別の登録名**で `join` してください。

<AnnotatedCommand
  who="guest"
  command="blugit join {<接続コード>} {demo2}"
  :notes="[
    ['接続コード', 'ホストが新しいリポジトリの共有を始めたときに表示された接続コードです'],
    ['新しい登録名', '前のリポジトリとは別の名前にします。同じ名前を使うとエラーになります'],
  ]"
/>

前のリポジトリの共有を再開すれば、前の登録名もそのまま使えます。
