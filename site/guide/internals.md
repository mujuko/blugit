# しくみ（読み物）

使うだけなら読まなくても大丈夫です。blugit の中で何が起きているのかを、もう少しくわしく知りたい人向けのページです。

## 接続コードの中身

<ConnectionCodeAnatomy />

接続コードは、ホストの Bluetooth アドレス（48ビット）と接続口の番号（5ビット）を、32種類の文字で書き表したものです。
11文字ぶんに情報を詰めて、最後に打ち間違いを見つけるためのチェック文字（CRC）を1文字付けています。

使う文字は、数字と英大文字から、読み間違えやすい `I`・`L`・`O`・`U` を除いた32種類です。
入力するときは、`O` を `0`、`I` と `L` を `1` として読み替えるので、聞き間違いや見間違いにも強くなっています。

## 登録のしくみ

6桁の確認番号は、ネットワークに流れません。ホストとゲストは、それぞれが知っている番号をもとに同じ暗号鍵を作り、その鍵でお互いを確かめ合います。
番号が違えば鍵も違うので、確かめ合いに失敗して登録は保存されません。

確かめ合いに成功すると、お互いの端末の公開鍵を交換して保存します。2回目からは、この鍵を使って接続します。

確認番号には、何度も試されないように次の制限があります。

| 制限 | 値 |
|---|---|
| 有効期限 | 180秒 |
| 入力できる回数 | 1回 |
| 同時に受け付ける申請 | 1件 |
| 番号を出す間隔 | 10秒以上 |

## Gitの通信

登録後のGitの通信は、Bluetooth の上で SSH を使って行います。
SSH は blugit の中に組み込まれているので、OS の SSH サーバーの設定や、アカウントの作成はいりません。

- ゲストは、登録のときに保存したホストの鍵と一致する相手にだけ接続します。
- ホストは、登録済みの端末の鍵で認証できた相手にだけ、Gitの操作を許可します。
- 許可するのは、共有中の bare リポジトリへの fetch と push だけです。ゲストがほかのファイルを開いたり、コマンドを実行したりすることはできません。

## Gitと blugit のつながり

`git clone blugit://demo` を実行したとき、裏では次のことが起きています。

1. Gitは、`blugit://` で始まる場所を見て、`git-remote-blugit` に接続を任せます。
2. `git-remote-blugit` は、保存してある登録名 `demo` の情報（ホストの住所・接続口・鍵）を読み出します。
3. Bluetooth でホストに接続し、保存した鍵でお互いを確かめ合います。
4. ホストの blugit が、共有中の bare リポジトリに対して Git を動かし、データを送り返します。

## 接続口が変わったとき

ホストは起動するたびに、空いている接続口を選びます。そのため、再起動すると接続口の番号が変わることがあります。

登録済みのゲストは、保存してある住所のホストで、接続口を探し直します。
見つけた相手が、保存してある鍵と共有中のリポジトリの情報に一致したときだけ、新しい番号を保存します。確認番号の入力や、登録し直しは必要ありません。

## 保存しているもの

| 保存しているもの | 場所 | 役割 |
|---|---|---|
| 端末の鍵と名前 | 各PCの保存先（[鍵と登録情報の保存先](./commands#鍵と登録情報の保存先)） | 端末を見分け、通信相手を確かめる |
| 登録名と接続先 | ゲストの保存先 | `blugit://登録名` から接続先を探す |
| 共有の情報と許可した端末 | ホストの保存先 | 誰にアクセスを許すかを決める |
| `.blugit-share.json` | ホストの bare リポジトリの中 | そのリポジトリを見分ける |
