# なぜblugit？

blugit は、近くのPC同士を Bluetooth でつないで、Gitのリポジトリを共有するための道具です。
どんなときに役立つのか、ひとつの例で見てみましょう。

## たとえば、こんな場面

ある会社に、社外からゲストを招いて、一緒にプログラムを作ることになりました。

- 社員のPCは、社内のGitHubにアクセスできます。
- ゲストのPCには社内のアカウントがないので、社内のGitHubは使えません。
- 2台とも同じ社内Wi-Fiにつながっていますが、このWi-Fiは**端末同士が直接通信できない**設定になっています。

<WifiScenario variant="before" />

同じ部屋の、同じWi-Fiにいるのに、隣のPCとコードをやりとりする方法がありません。

::: info 端末同士が通信できないWi-Fi
公共のWi-Fiや来客用のWi-Fiでは、つないだ人どうしが互いのPCにアクセスできないように、端末間の通信を止めていることがよくあります。
インターネットには出られても、隣のPCには届かないのです。
:::

## これまでの回避策と、困るところ

よくあるのは、USBメモリやファイルの送受信で、フォルダごと受け渡す方法です。

- 渡すたびに手作業が必要で、どちらが新しいのか分からなくなりがち
- それぞれが変更した内容を、手で見比べてまとめないといけない
- 「いつ・誰が・何を変えたか」という履歴が1つにまとまらない

これでは、[Git講座](../git/#intro)で見た「最終版_本当に最終」問題に逆戻りです。

## blugit を使うと

blugit は、Wi-Fi もインターネットも使わずに、2台のPCを Bluetooth で直接つなぎます。

<WifiScenario variant="after" />

- どちらかのPCが<Role who="host" />になって、リポジトリを共有します。
- もう一方は<Role who="guest" />として、最初に1回だけ登録します。
- あとは `git clone blugit://demo`、`git push`、`git pull` と、いつものGitコマンドでチーム開発ができます。

アカウントの作成や、サーバーの設定は必要ありません。

## どちらがホストになる？

どちらがホストになっても、チーム開発はできます。決めるときは、次の点を目安にしてください。

- ホストは、共有している間 `blugit host` を起動したままにしておく必要があります。PCを閉じたり、スリープさせたりしないでください。
- ホスト自身も、普通に作業に参加できます（[はじめての共有](./first-share#ホスト自身も編集するには)で説明します）。
- ゲストが何人いても、それぞれのPCで登録すれば同じリポジトリを使えます。

## 向いている場面・向かない場面

| 向いている | 向かない |
|---|---|
| 同じ部屋にいる数人で、リポジトリを共有する | 離れた場所にいる相手との共有 |
| コード中心の、小さめのリポジトリ | 画像や動画など、大きなファイルが多いリポジトリ |
| ネットワークがない、または使えない場所での作業 | 機密情報を扱う業務（組織で管理する開発基盤を使ってください） |

Bluetooth の通信は、Wi-Fi よりゆっくりです。実際に測った例では、6 MiB のリポジトリの最初の clone に約50秒かかりました。
その後の push や pull は、変更が小さければ1秒程度で終わります。

## 使う前の確認

- 両方のPCに、Bluetooth Classic に対応した Bluetooth があること（[動作環境](./install#動作環境)）
- 両方のPCに、Git と blugit をインストールしておくこと
- インストールにはインターネット接続が必要なので、当日より前に済ませておくこと

準備ができたら、まず[blugitのしくみ](./overview)をざっと眺めてから、[はじめての共有](./first-share)に進みましょう。
